## 4. 问题一：公开入口的“身份证”没有改

当前代码在 `torch_npu/profiler/__init__.py` 中导出了函数：

```python
from ._inductor_profiler import inductor_trace_handler

__all__ = [
    # 其他已有公开入口……
    "inductor_trace_handler",
]
```

但是 Python 不会因为 `from ... import ...` 自动修改函数的所属模块：

```python
inductor_trace_handler.__module__
# "torch_npu.profiler._inductor_profiler"
```

`TestPublicBindings.test_correct_module_names` 同时要求：API 在公开列表里，且
`__module__` 属于当前公开命名空间、不能含 `._`。我们满足前一条，不满足后一条。

修复方向是正确声明公开 API 所属模块，例如 `torch_npu.profiler`；**不应为了让测试绿灯
就删掉 `__all__` 中的入口，或把它加进豁免名单**。用户入口仍应保持：

```python
from torch_npu.profiler import inductor_trace_handler
```

本轮源码契约检查已经重现这个元数据不匹配；产品代码尚未修改。

## 5. 问题二：PyTorch 2.15 多传了一个参数，NPU 子类没有接住

失败的关键调用链是：

```text
compiled_model(input)
  → Inductor lowering / scheduler / codegen
  → NPUTritonKernel.load(...)
  → super().load(...)                    # PyTorch 的 TritonKernel.load
  → self.indexing(..., allow_reduction_invariant_indexing=...)
  → NPUTritonKernel.indexing(...)         # 回调到 NPU 子类
  → TypeError: unexpected keyword argument
```

NPU 当前签名没有这个参数，也没有接收额外关键字参数的入口：

```python
def indexing(self, index, *, copy_shape=None, dense_indexing=False,
             override_mask=None, block_ptr=False,
             tma_compatibility_checker=None, mask_constant_index=False):
    ...
```

本轮用 AST 对照确认：该 `indexing` 方法与最新 `origin/master` 完全相同；PR 的 codegen
改动是在调度/launch 处补 provenance 记录，没有修改这个方法。

这说明它是 **NPU 后端与上游新接口之间的兼容缺口，被新增用例暴露出来**。但仍需在
CI 匹配环境做关闭/开启 provenance 的对照，不能只凭代码未改就宣布全链路与本 PR 无关。

影响的 7 项：timeline forward/backward、rsplit 双 launch、FFN、attention、Llama
SwiGLU、ConvNeXt、Transformer encoder。

为什么不是 Triton Ascend 编译器报错？日志停在 Python 方法参数绑定，没有进入本次
kernel 的 Triton/MLIR 编译调用。日志中已有 `ops.load` 的 Pointwise IR，说明并不是
“算子没注册、没有进入图”。CI 记录了 `/tmp/tmp*/torchinductor/...` 调试目录，但本地
未取得这些远端 `output_code.py` 工件；不拿历史生成代码冒充本轮证据。

修复时需要同时处理 2.14 旧签名和 2.15 新签名：**不能直接把新参数无条件传给所有
版本的父类，也不能默默丢掉参数而忽略其语义**。应核对新参数的含义，补版本兼容路径，
并分别验证旧版无参数调用、新版传参调用及真实 NPU 编译。
